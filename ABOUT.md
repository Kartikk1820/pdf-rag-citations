# About This Project

## What it is

**PDF RAG with Citations** is a web application that lets you upload PDF documents and ask
questions about them in plain English. It answers **strictly from the content of your PDFs** and
always tells you exactly which document and page the answer came from — so you can verify every
claim instead of just trusting the AI.

If your documents don't contain the answer, it says so honestly instead of making something up.
If you ask it something casual ("hi") or something general ("what's the capital of France?") that
your documents don't cover, it can still answer naturally — but it always makes clear when an
answer is **not** backed by your documents, so the two are never confused.

## The problem it solves

Ask ChatGPT (or any plain LLM) a question about a document, and two things can go wrong:
1. It might answer from its own general training data instead of your actual document.
2. If you ask it to cite a page number, it can simply **make one up** — a confident-sounding but
   fake citation. This is called "hallucination," and it's one of the most-cited criticisms of
   LLM-based tools in serious use cases (legal, HR, compliance, research).

This project is built specifically so that **can't happen** for document answers. The page
number and file name attached to every citation are never generated by the AI — they're looked up
by the application itself from data it recorded when the PDF was first processed. The AI's only
job is to say *which* retrieved passage it used (by number); the app fills in the real source.
That makes citations correct by construction, not "correct because the model tried hard."

## What makes it more than a basic "chat with your PDF" demo

Most tutorials build this with one step: embed the text, do a vector similarity search, done.
This project goes several steps further:

- **Hybrid search** — combines keyword search (BM25, same family of technique as traditional
  search engines) with AI-based semantic/meaning search, so it finds the right passage whether you
  use the exact words from the document or completely different phrasing.
- **Query rewriting** — before searching, the AI generates 2-3 alternative ways of phrasing your
  question, so a single oddly-worded question doesn't fail to find the right information.
- **Reranking** — after the initial search, a second, more precise AI model re-scores the top
  candidates by actually reading the question and the passage together, rather than just comparing
  two numbers. This second-pass score is also what decides whether the system should even attempt
  an answer, which is a much more reliable gate than the simpler approach most tutorials use.
- **Streaming answers** — responses appear word-by-word as they're generated, like ChatGPT, instead
  of a long pause followed by a wall of text.
- **Multi-turn conversation** — you can ask a follow-up question ("what about page 2?") and it
  understands what you're referring to from the earlier exchange.
- **A general-knowledge fallback, clearly labeled** — casual messages get a normal reply, and
  genuine questions the documents don't cover get answered from general knowledge, visibly marked
  as such, instead of a cold "I don't know" every time.
- **Observability** — every question asked is logged with how long it took and how confident the
  system was, visible on an Analytics screen, not just a black box.
- **All of this runs for free, locally** — the search engine, the AI model that does the
  reranking, and the text-to-numbers embedding step all run on your own machine for $0 — only the
  final answer-writing step calls an external AI provider, and that provider has a free tier.

## The 5 screens

| Screen | What you do there |
|---|---|
| **Dashboard** | See how many documents are indexed, how many questions have been answered, and which features (hybrid search, query rewriting, etc.) are currently on. |
| **Document Library** | Upload PDFs (drag-and-drop or the Upload button) and click one button to index them. |
| **Chat** | Ask questions. Answers stream in live, with a confidence score and a clickable link straight to the source page for every citation. |
| **Analytics** | See every question that's been asked, how fast it was answered, and how confident the system was. |
| **Settings** | Change the AI provider/model, or tune how retrieval behaves — all from the browser, no file editing required. |

## Technology used (plain-English version)

| What | Why |
|---|---|
| Python | The language the whole backend is written in. |
| FastAPI | Serves the web pages and the API the browser talks to. |
| Qdrant (embedded) | Stores the documents' "meaning vectors" for semantic search. Runs as a local file, not a separate server. |
| fastembed | Turns text into those meaning vectors, and also does the reranking step — both run fully offline, no cost. |
| rank_bm25 | The keyword-search half of hybrid search. |
| OpenRouter / Groq | The AI provider that writes the actual answer text. Both have free tiers. |
| SQLite | Stores the Analytics history, as a single local file. |
